一、它是怎麼運作的

整套系統只有三個東西。先認識它們，後面就都看得懂了。

第 1 個
網頁
客人用手機打開，選項目、選時間、填資料。就像店門口的一塊看板，只是客人可以在上面寫字。
第 2 個
小幫手
看不見的程式，住在 Google 裡。客人一按送出，它負責把資料抄到預約本、再寄信通知你和客人。
第 3 個
預約本
一份 Google 試算表，名字叫「預約紀錄」。所有預約都會自動寫在這裡，你也可以直接在上面改。
為什麼要知道這個？

因為出問題時，你要先判斷是「哪一個」壞掉。網頁沒更新、小幫手沒反應、預約本沒進資料——是三件不同的事，修法也不一樣。第五段的表格會幫你分辨。

目前支援五種語言

中文、英文、日文、韓文、阿拉伯文。網頁會自動判斷客人手機的語言， 客人也可以自己按右上角切換。阿拉伯文是由右往左讀的，整個版面會自動鏡射， 這是正常的，不是壞掉。

網頁還會自己做兩件事

第一，它會去問預約本「哪些時段已經有人約了」，然後把那些時段變成灰色，客人就點不下去。 這樣兩個客人不會約到同一個時間。

第二，它會擋住太近的日期。規定是「今天起七天之後」才能約，所以客人打開時， 最近七天的日期全部是灰的，點不動。

二、有人預約時，你要做什麼

客人按下送出之後，這些事會自動發生，你只要做最後兩步。

誰做什麼
小幫手把預約寫進預約本，狀態自動填「待確認」
小幫手寄一封通知信給你，標題像 [新預約 ECC-260930-A3F2]
小幫手寄一封確認信給客人，用客人選的語言
你看信、確認時間可以，回信告訴客人
你客人當天轉帳後，在預約本把狀態改成「已確認」
回信最快的方法

直接按通知信的「回覆」。那封信設定好了，回覆會直接寄到客人的信箱，不用另外複製貼上。

客人取消或改期

在預約本找到那一列，把「狀態」欄改成 已取消。 只要有「取消」兩個字就算數。

改完之後，那個時段會自動變回可以預約，別的客人就能約走了。 不要刪掉整列——留著紀錄比較好查，而且改狀態就已經達到目的了。

三、我想改東西

幾乎所有設定都在同一個檔案裡，叫 config.js。 它在 GitHub 的 eternitychildbooking 資料夾裡。

先記住這個開檔步驟

下面每一則都要先做這三步：打開 GitHub 的 eternitychildbooking 資料夾 → 點要改的檔案 → 點右上角的鉛筆圖示，就可以編輯了。改完往下捲，按綠色的 Commit changes 存檔。

換照片 最常做

  1. 把新照片改名成 photo-1.jpg（或 2、3、4）。
  2. 打開 eternitychildbooking/assets 資料夾。
  3. 右上角 Add file → Upload files，把照片拖進去。
  4. 按 Commit changes。

檔名一樣就是「換掉舊的」，不用先刪。照片建議是正方形、寬 800～1200、 每張不超過 300KB。photo-1.jpg 比較特別，它同時是貼到 LINE 時顯示的那張預覽圖，挑最好看的放。

改營業時間

打開 config.js，找到 hours 這一段。數字 0 是星期日、1 是星期一，一直到 6 是星期六。

  1. 找到要改的那一天。
  2. open 是開門時間，close 是關門時間。
  3. 照原本的格式改，例如把 '21:00' 改成 '20:00'。
兩個特別的規則

星期日那行有 firstVisitOnly: true，意思是「只有初診可以約」。 不想要這個限制，把這一段刪掉即可。
另外，系統會自動確保療程能在關門前做完。例如關門 17:00、療程 40 分鐘， 最晚就只能約 16:00，這不用你算。

改價格

價格有兩個地方，因為有兩種算法。

  1. 按時間算的（量子整骨等四項）：找 prices， 40: 1688 就是 40 分鐘 1688 元。
  2. 選部位算的（醫美整骨）：找 packages， pick: 3 是選三項、price 是價錢、 minutes 是要佔用幾分鐘的時段。目前有三個方案： 擇三、擇五，以及十項全選的「精雕細琢 × 表面功夫」。

加公休日

打開 config.js，找到 closedDates。把日期寫進中括號裡，格式是「年-月-日」，要加引號和逗號。

closedDates: ['2027-01-01', '2027-02-14'],

寫進去的日期，客人就點不到了。

換地圖

  1. 到 Google 地圖搜尋新地址。
  2. 點分享 → 選嵌入地圖 → 複製那一整段。
  3. 那段裡面有一個 src="..."，把引號中間的網址複製下來。
  4. 貼到 config.js 的 map 裡，取代 embed 原本的網址。

改收預約的信箱

這個不在網頁裡，在小幫手那邊。因為信是小幫手寄的，不是網頁寄的。

  1. 打開預約本（Google 試算表）。
  2. 上方選單 擴充功能 → Apps Script。
  3. 找到最上面的 CENTER_EMAIL，把信箱改掉。
  4. 存檔，然後重新部署（做法看下一段的警告框）。

四、改完一定要做的事

這一段最重要。漏了它，你改的東西客人看不到，而且完全沒有錯誤訊息。

如果你改的是網頁（config.js、照片以外的檔案）

要把「版本號」加一號，總共兩個地方，必須改成一樣的數字：

檔案找什麼改成
config.jsversion: '1.9'version: '2.0'
index.html四個 ?v=1.9四個 ?v=2.0
為什麼要這樣？

瀏覽器怕慢，會把網頁影印一份存在自己身上，下次直接看影印本。 你改了網頁，它還在看舊的影印本，怎麼重新整理都一樣。 版本號加一，等於幫檔案換了一個新名字，瀏覽器發現「這是沒看過的東西」， 就會重新去拿一份新的。

改完等一兩分鐘，打開網站看頁尾右下角的版本號。 變成新的數字，就代表成功了。這是最快的檢查方法。

如果你改的是小幫手（Apps Script）

存檔不會生效，一定要重新部署：
部署 → 管理部署作業 → 右上角鉛筆 → 版本選「新版本」→ 部署
用這個方式更新，網址不會變，不用回去改設定。 如果誤按成「新增部署作業」，會拿到另一組網址，那就得回去更新 config.js 了。

五、出問題了

照著症狀找，從上往下試。

你看到的狀況多半是這個原因怎麼修
改了東西，網站上看不到 版本號沒加，或瀏覽器還在看舊的影印本 先按 Ctrl+Shift+R（Mac 是 Cmd+Shift+R）強制重新整理。還是舊的，就是版本號忘了加，回第四段
客人說有預約，但預約本沒有 小幫手沒更新，或部署沒做 打開網站按 F12，看最上面那行寫的收單網址。寫「未設定」就是網頁是舊的；有網址就去重新部署小幫手
預約本有資料，但沒收到信 Gmail 當天寄信額度用完，或信被丟進垃圾信匣 先翻垃圾信匣。都沒有就等隔天，額度每天會重置
網頁上的地圖不見了 某些環境會擋掉外部地圖 不用修。地圖下面本來就有「在 Google 地圖開啟」的連結可以點
照片沒出現 檔名不對 檔名必須剛好是 photo-1.jpg 到 photo-4.jpg，大小寫和副檔名都要一樣
某個時段該開放卻是灰的 預約本裡有一筆佔著它 去預約本找那個日期時間，把「狀態」改成 已取消
想確認小幫手本身有沒有壞

打開預約本 → 擴充功能 → Apps Script，上方函式選單選 testWrite，按執行。 它會自己假裝有人預約，走完全部流程。預約本多一列、你收到信，就代表小幫手是好的， 問題出在網頁那邊。
不要選 doPost 執行，那個一定會出現紅字，那是正常的，不是壞掉。

六、千萬不要做的事

這幾件事會讓系統壞掉，而且不容易救回來。

不要做
  • 不要刪掉預約本，也不要改它的分頁名稱。分頁必須叫「預約紀錄」，小幫手是靠這個名字找到它的。
  • 不要改預約本第一列的欄位名稱，也不要調換順序。小幫手是照順序讀的，換了就會抄錯格。
  • 不要刪掉整列預約。要放掉時段，把狀態改成「已取消」就好。
  • 不要改照片的檔名規則。一定是 photo-1.jpg 到 photo-4.jpg。
  • 不要在 config.js 裡刪掉逗號或引號。少一個符號整個網頁就打不開。只改引號中間的內容最安全。
  • 改完不確定對不對，先不要關掉頁面。GitHub 每次存檔都會留紀錄，真的改壞了可以找回來——但先問過再動比較快。

七、名詞解釋

聽到這些字不用緊張，意思其實很單純。

GitHub
放網站檔案的地方，也會自動幫你把網站發佈出去。 就像一個公用的檔案櫃，而且你每改一次，它都會拍照存證，改壞了可以翻回去。
Apps Script
寫在 Google 試算表裡的小程式，也就是這本手冊說的「小幫手」。 像是請了一個工讀生，專門負責抄寫和打電話通知。
部署
把改好的小幫手「正式上工」的動作。 你改了工讀生的工作說明書，但沒告訴他。部署就是通知他「從現在起照新的做」。沒部署，他還是照舊的做。
快取
瀏覽器把看過的網頁存一份在自己身上，下次開比較快。 像把課本影印了一份放抽屜。老師改了課本，你還在看影印本。強制重新整理，就是去拿新的那本。
Commit
在 GitHub 上按下「存檔」。 沒按這個，你改的東西只是寫在螢幕上，沒有真的存進去。
版本號
網頁頁尾右下角那個 v1.8。 用來確認「現在網站上跑的是哪一版」。你改完後它有變，就代表更新成功了。
