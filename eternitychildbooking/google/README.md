# 用 Google 試算表收預約（推薦）

免費、不用主機、不用外掛。預約送出後會同時：

1. 在 Google 試算表新增一列（含「狀態」欄，可直接當後台管理）
2. 寄一封通知信到 `ahanamita88888888@gmail.com`（按「回覆」就是回信給客人）
3. 依客人選的語言，自動回一封 HTML 排版的確認信給客人（中／英／日／韓），
   內含日期、服務名稱、部位——都會用客人自己的語言呈現
4. **把已成立的時段回報給預約頁，讓其他客人看到那個時段已被約走**

資料只經過你自己的 Google 帳號，不經任何第三方服務。

---

## ⚠️ 已經部署過的話，改了程式要重新部署

Apps Script **不會**因為你存檔就更新線上的版本。每次改完程式都要：

`部署 → 管理部署作業 → 右上角鉛筆（編輯）→ 版本選「新版本」→ 部署`

用「管理部署作業」的方式更新，`/exec` 網址**不會變**，不用再改一次程式碼裡的設定。
如果改成「新增部署作業」就會拿到另一組網址，那才需要回去更新 `endpoint`。

---

## 部署步驟（約 5 分鐘）

**1. 建立試算表**
到 [sheets.new](https://sheets.new) 開一個新的 Google 試算表，取名例如「永恆之子預約紀錄」。

**2. 貼上程式**
在該試算表點 `擴充功能 → Apps Script`，把預設的程式碼全部刪掉，
改貼上本資料夾的 `booking-sheet.gs` 全部內容，按存檔（💾）。

**3. 部署成網頁應用程式**
右上角 `部署 → 新增部署作業`：

| 欄位 | 選擇 |
|:---|:---|
| 類型（左上齒輪） | 網頁應用程式 |
| 執行身分 | **我**（你自己的帳號） |
| 誰可以存取 | **所有人** |

按「部署」。第一次會跳出授權畫面——選你的 Google 帳號，
看到「Google 尚未驗證這個應用程式」時點 `進階 → 前往「未命名的專案」（不安全）`，
再按「允許」。這是你自己寫的程式，授權對象是你自己。

**4. 複製網址、貼進設定**
部署完成後會給你一段像這樣的網址：

```
https://script.google.com/macros/s/AKfycb.................../exec
```

打開 `index.html`（或 `standalone.html`），搜尋 `endpoint`，改成：

```js
endpoint: 'https://script.google.com/macros/s/AKfycb.................../exec',
```

存檔上傳，完成。

## 確認有沒有成功

**先測部署**：把 `/exec` 網址直接貼到瀏覽器打開，看到這樣就對了：

```json
{"ok":true,"service":"永恆之子整椎中心","sheet":"預約紀錄"}
```

**再測防撞單**：在網址後面加上 `?action=slots` 打開，會看到已被預約的時段：

```json
{"ok":true,"taken":{"2026-09-30":[[540,600]]}}
```

數字是從當天 00:00 起算的分鐘數，540 = 09:00、600 = 10:00。試算表沒資料時是 `{}`。

**再測整條流程**：到預約頁自己送出一筆假預約，然後檢查

- 試算表有沒有多一列
- 信箱有沒有收到「[新預約 ECC-…]」
- 你填的那個客人信箱有沒有收到確認信

三個都有就完成了。接著重新整理預約頁，剛剛約掉的那個時段應該已經變成反灰。
測試完把試算表那一列刪掉即可。

> **要放掉某個時段**：不用刪列，把「狀態」欄改成「已取消」就好，
> 那個時段會立刻重新開放預約，紀錄也還留著。

## 想在編輯器裡直接測試？請執行 testWrite，不要執行 doPost

**在編輯器上方的函式選單直接選 `doPost` 按「執行」一定會失敗**，
錯誤會出現在 `JSON.parse(e.postData.contents)` 這一行，偵錯工具裡會看到 `e: undefined`。

原因是 `doPost(e)` 的 `e` 是「網路請求送進來時」才會產生的物件，
從編輯器手動執行不會有人幫你帶入，這跟你的部署有沒有問題無關。

要手動測試，請在函式選單改選 **`testWrite`** 再按執行。它會模擬一筆預約，
完整跑過「寫入試算表 → 寄通知信 → 寄確認信」，結果會顯示在下方的「執行記錄」。
跑完記得把試算表裡那一列測試資料刪掉。

## 收不到的話，照這個順序查

| 症狀 | 原因與解法 |
|:---|:---|
| 執行 `doPost` 出現 `e is undefined` | 正常現象，不是錯誤。改執行 `testWrite`（見上一節） |
| 執行 `testWrite` 說「找不到試算表」 | 這支程式不是從試算表開啟的。請從試算表的「擴充功能 → Apps Script」重開，或把試算表網址中的 ID 填進程式最上方的 `SPREADSHEET_ID` |
| `testWrite` 成功但線上預約沒進來 | 部署沒更新。「部署 → 管理部署作業 → 鉛筆 → 版本選新版本 → 部署」 |
| `/exec` 網址打不開或要求登入 | 部署時「誰可以存取」沒選「所有人」。重新部署一次 |
| 試算表沒新增列 | `endpoint` 沒貼對，或貼成 `/dev` 結尾的網址（要用 `/exec`） |
| 試算表有列、但沒收到信 | Gmail 每日寄信有配額上限；也看一下垃圾信匣 |
| 想看失敗原因 | Apps Script 左側「執行記錄」會留下每次呼叫的錯誤訊息 |
| **testWrite 成功，但從網頁送出還是沒進來** | **多半是網站上跑的是舊版**。看頁尾右下角的版本號，或按 F12 打開主控台，載入時會印出這份頁面把預約送去哪裡；顯示「未設定」就代表跑的是舊檔 |
| 已經部署了，頁尾版本號還是舊的 | 瀏覽器快取。強制重新整理（Windows `Ctrl+Shift+R`／Mac `Cmd+Shift+R`），或用無痕視窗開一次 |

送出失敗時，預約頁會**自動退回**「開啟客人的信箱程式」那條路，
所以就算後端出問題，預約也不會直接消失。

## 第一次貼上新版程式後，要做的兩件事

貼上 `booking-sheet.gs` 並存檔之後：

**1. 重新部署**
`部署 → 管理部署作業 → 右上角鉛筆 ✏️ → 版本選「新版本」→ 部署`。
**網址不會變**，預約頁不用改。沒有做這一步的話，網頁用到的還是舊程式。

第一次會再跳一次授權畫面（因為程式碼裡多了行事曆功能），一路按「允許」即可。
行事曆功能預設是**關閉**的，在關閉狀態下程式不會去讀寫任何行事曆。

**2. 到試算表開啟狀態選單**
回到試算表，重新整理一次網頁，功能表列會多出「**預約管理**」，
點一次 `重新設定狀態選單與顏色`——C 欄「狀態」就會變成下拉選單，取消的列會變灰。

## 取消預約：怎麼把時段放回去

在試算表找到那一列，把 **C 欄「狀態」** 選成 `已取消`。會同時發生兩件事：

1. 該時段重新開放預約（客人的頁面約 30 秒後、或重新整理就看得到）
2. 那一列變灰，一眼看得出已經取消

也可以點一下那一列，用 `預約管理 → 把選取的預約標為「已取消」`，一次處理多列，
處理完會跳出提示告訴你改了哪幾位客人。

> 狀態只要含「取消」兩個字就算取消。改用下拉選單就是為了避免打錯字——
> 打成「取銷」的話時段是解不開的。

「預約管理」選單還有一個 `查看目前已佔用的時段`，可以快速確認目前哪些時段是滿的。

## （選用）把預約同步到 Google 日曆

**預設關閉。** 因為活動會建在「執行這支程式的那個帳號」的行事曆上——
如果程式是網頁維護者的帳號部署的，開啟後預約會跑進維護者的私人行事曆，
而不是中心的行事曆。

要讓預約出現在**中心的**行事曆，先請中心的帳號分享行事曆：

1. 中心帳號登入 Google 日曆 → 左側找到要用的行事曆 → `⋮ → 設定和共用`
2. 「與特定使用者或群組共用」→ 加入**執行這支程式的那個帳號**
3. 權限選 **「變更活動」**（只給「查看」的話程式無法建立活動）

再到 Apps Script 把最上面兩行改成：

```js
const CALENDAR_ENABLED = true;
const CALENDAR_ID = 'ahanamita88888888@gmail.com';   // 中心的行事曆 ID，通常就是 email
```

存檔 → 重新部署（同上，版本選「新版本」）→ 回試算表重新整理，
「預約管理」會多出兩個項目，各點一次：

- `開啟行事曆自動同步` → 之後在試算表改狀態，行事曆會自動跟著變
- `把現有預約補建到行事曆` → 把今天以後、還沒同步的預約一次補上

開啟後的行為：

| 試算表 | 行事曆 |
|:---|:---|
| 新預約進來 | 建立活動 `⏳ 王小明　量子整骨（40 分）` |
| 狀態改「已確認」 | 標題圖示變 ✅ |
| 狀態改「已取消」 | 活動移除 |
| 改了日期或時間 | 活動跟著移動 |

活動的說明欄裡有服務、部位、加贈、費用、電話、Email、匯款末五碼、備註，
開始前 60 分鐘會跳提醒。活動 ID 存在試算表最後一欄「行事曆ID」，不用去動它。

想把預約獨立成一本日曆（跟私人行程分開），改用
`const CALENDAR_NAME = '永恆之子預約';`（`CALENDAR_ID` 留空），程式會自動幫你建。

> 客人那邊不受影響：確認信裡本來就有「加入行事曆」按鈕，客人自己按就能加到
> 他自己的日曆，跟這個設定無關。

## 防撞單是怎麼運作的

預約頁在開啟時、以及客人進到「選擇時間」那一步時，會向 `?action=slots` 讀回
已成立的時段（30 秒內不重複查詢），再把會重疊的時段鎖住。

判斷是「區間重疊」而不是「開始時間相同」——例如別人約了 09:00–10:00，
那麼 09:30 開始的 40 分鐘療程（做到 10:10）也會一併鎖住。

如果 Google 那邊暫時連不上或回傳異常，預約頁會照常運作，只是暫時看不到
別人的預約。這是刻意的取捨：寧可偶爾撞單，也不要讓客人完全無法預約。
