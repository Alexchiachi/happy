# Inner Flow Assessment（WordPress 外掛）

購買後生成《自洽躍遷破局手冊》：驗證 Gumroad 授權碼 → 以 DeepSeek **分章生成** →
報告頁呈現並可列印成 PDF。專為 cPanel 共享主機設計，不需要另外架伺服器。

## 為什麼要分章生成

一份報告完整生成要 1–2 分鐘，但共享主機的 `max_execution_time` 常見只有 30–60 秒，
前面若有 Cloudflare 還有約 100 秒的閘道逾時。**同步生成必定中斷，而且是在使用者付完錢之後中斷。**

因此這個外掛把一份報告拆成 **6 個步驟**（五章 + 寄語），每個步驟是一次獨立的短請求，
約 20–30 秒，穩穩落在任何主機的限制之內。使用者在解鎖頁看到章節一段一段長出來，
兩分鐘的等待因此是有進度感的等待。

推進靠三條路徑，只要有一條活著報告就會完成：

1. **非阻塞 loopback 請求**——最快，多數主機可用
2. **WP-Cron 單次事件**——loopback 被擋時的後備
3. **前端輪詢的自我修復**——輪詢時若發現任務超過 120 秒沒有進度，由輪詢本身推它一把

任務狀態存在資料庫，取鎖用單一 `UPDATE` 完成，因此三條路徑同時醒來也不會重複生成、重複花錢。

## 安裝（cPanel）

1. 把 `inner-flow/` 整個資料夾上傳到 `wp-content/plugins/`，在後台啟用（啟用時會自動建表）。
2. 在 `wp-config.php` 的 `/* That's all, stop editing! */` **之前**加入：

   ```php
   define( 'INNER_FLOW_DEEPSEEK_KEY', 'sk-你的金鑰' );
   define( 'INNER_FLOW_GUMROAD_PRODUCT_ID', '你的-gumroad-product-id' );
   // 可選，預設 deepseek-chat
   define( 'INNER_FLOW_DEEPSEEK_MODEL', 'deepseek-chat' );
   ```

   金鑰放這裡而不是資料庫：資料庫的 options 表任何外掛都讀得到，也會進到備份與匯出檔。

3. 建立兩個頁面：
   - **解鎖頁**：內容放 `[inner_flow_unlock]`（購買完成後導向這裡）
   - **報告頁**：內容放 `[inner_flow_report]`
4. 到「設定 → Inner Flow」選擇報告頁，並填入四段語音導引的網址。
5. 打開 `https://你的網域/wp-json/inner-flow/v1/health` 確認金鑰與商品 ID 都顯示已設定。

測驗頁（`inner-flow.html`）可以用「自訂 HTML」區塊嵌入，或維持在 GitHub Pages。
它會把測驗結果寫進 `localStorage`，解鎖頁再讀出來——所以使用者去 Gumroad 結帳再回來，
結果還在。

## 四段語音導引（真人錄音）

DeepSeek 沒有語音合成端點，而合成語音也配不上這個價位。四種原型各錄一段即可，
一次錄好長期使用：

| 原型 | 建議長度 | 內容方向 |
| --- | --- | --- |
| 邊界滲漏型 | 8–10 分鐘 | 先立牆：想像能量的邊界重新長出來 |
| 次生擾動型 | 8–10 分鐘 | 讓未走完的情緒走完，停止重播 |
| 完美主義凍結型 | 8–10 分鐘 | 鬆開審判，允許先醜著存在 |
| 動態自洽型 | 6–8 分鐘 | 把餘裕投出去，允許有意義的失序 |

錄成 MP3 上傳到媒體庫，把網址填進設定頁即可。

## 成本與濫用防護

生成端點會花錢，因此預設就有三道閘門：

- **Gumroad 授權驗證**：沒有有效授權碼不會呼叫模型（`increment_uses_count=false`，
  次數由我們自己控管，買家因此可以重看報告）
- **每組授權碼最多 3 份報告**（重測後可再生成，但不能無限）
- **每個 IP 每小時最多 20 次建立請求**

另外，同一位買家的同一份測驗結果只會有一個任務（資料庫的 `license + code` 唯一鍵），
重新整理或重按都不會重複生成。

## 省錢的兩個設計

**上下文快取**：每次呼叫都由「固定前綴（人格設定 + 分數）+ 本章指令」組成，
前綴逐字相同，因此六次呼叫共用同一段快取——DeepSeek 會自動以較低費率計價。
改動 `Prompts::context_prefix()` 等於讓快取失效。

**該用模板的不用模型**：封面、能量座標、三維度定義、熵值公式、免責聲明都由 PHP 產出，
只有五章與寄語交給模型。省錢、更快，也少一個幻覺來源。

## 品質把關

模型輸出在寫進資料庫前必須通過 `Quality::check()`：字數不足、出現雞湯句
（「加油」「相信自己」…）、混入 markdown 標記都會退回重寫，並在重寫時附上更嚴格的指令。
連續三次不合格才判定失敗。這比在提示詞裡多寫十條禁令有效得多。

## 報告篇幅

五章各 500–900 字、寄語 150 字以內，加上四頁模板骨架，實際約 **13–15 頁**。
報告首頁的頁數是依實際內容算出來的（`ReportBuilder::estimate_pages()`），
不是憑空喊的數字——銷售頁若要寫頁數，用這個。

## 測試

```bash
php tests/run.php
```

16 項測試涵蓋狀態機（分步生成、鎖、重試、卡住偵測）、品質把關、授權驗證、
提示詞前綴的一致性與報告組裝。以記憶體儲存與 HTTP 替身執行，
不需要 WordPress，也不需要真的 API 金鑰。

## 端點

| 方法 | 路徑 | 說明 |
| --- | --- | --- |
| GET | `/wp-json/inner-flow/v1/health` | 設定狀態（不回傳金鑰） |
| POST | `/wp-json/inner-flow/v1/report` | 驗證授權碼並建立任務 |
| GET | `/wp-json/inner-flow/v1/report/{job}` | 輪詢進度，回傳已完成的章節 |
| POST | `/wp-json/inner-flow/v1/work` | 背景推進一步（HMAC 權杖保護） |
