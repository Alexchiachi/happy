# 決策紀錄：daoissimple.com 的 WordPress 內容維護，不走自動化

**日期**：2026-08-29
**結論**：**不接自動化。** 用後台編輯 + 對話寫稿，加上一個文章範本。
**下次重評時機**：見文末〈什麼時候該重新評估〉。

---

## 情境

| 項目 | 現況 |
| --- | --- |
| 站台 | daoissimple.com，WordPress + Blocksy 主題 |
| 主機 | cPanel 共享主機 |
| 測試站 | 沒有 |
| 備份 | 不確定（**這件事還沒解決，見文末**） |
| 內容節奏 | 幸福誌約 **每月 6 篇** |
| 想解決的 | 內容與文案維護 |

## 評估過的路徑

| 路徑 | 內容 | 為什麼不採用 |
| --- | --- | --- |
| **自己寫的 REST API 工具** | 一支 Python 腳本，拉頁面到本機改完推回去 | 產出不划算（見下）。而且要自己維護，官方方案出現後就沒有存在價值 |
| **官方 MCP Adapter 外掛** | WordPress core AI 團隊維護，免費 | 產出不划算。仍要應用程式密碼、本機 Claude Code、安全外掛放行 `/wp-json/` |
| **Jetpack + WordPress.com 連接器** | 官方、一鍵、手機也能用，寫入需確認 | 產出不划算，且需 Jetpack AI 或 Complete 付費方案 |
| **後台編輯 + 對話寫稿**（採用） | 什麼都不裝 | — |

## 為什麼不划算：瓶頸是照片，不是文字

表面上的算法是這樣：

- 每篇省下「貼進後台 + 排成區塊」約 10 分鐘
- 6 篇 × 12 個月 ≈ **每年 12 小時**

看起來划得來。但這個算法錯了。

**這個站的設計系統是照片主導的。** `docs/DAOISSIMPLE_SITE.md` 寫著「雲南建議山霧、
茶倉、職人雙手；台灣建議稻田、海岸、職人器物」。每一篇幸福誌都要進後台上傳照片、
挑圖、設首圖——這件事任何 AI 整合都幫不上，圖片走媒體庫，是手工活。

也就是說：**每發一篇，人都會待在後台。** 人已經在那裡了，順手貼一段文字的邊際成本
接近零——不是 10 分鐘，大概 2–3 分鐘。

重算：

- 6 篇 × 3 分鐘 = 每月約 15 分鐘
- **每年約 3 小時**

為了一年 3 小時，去養一條要付月費、要維護、會壞掉的整合鏈，不划算。

**自動化省下的，是一趟你本來就要走的路。**

## 改成做這兩件事

都免費，加起來十分鐘，省下的時間比任何整合都多。

### 一、做一個文章範本

在後台寫一篇草稿，把幸福誌的骨架排好（開場摘要 → 內文 → 引言區塊 → 圖說 → 分隔），
標題寫「_範本 · 不要發布」。之後每篇複製它來改，排版時間直接歸零。

這跟靜態站的 `journal/_template.html` 是同一個思路（見 `docs/ADD_JOURNAL_POST.md`），
本來就對，搬到 WordPress 就好。

### 二、寫稿時貼上品牌守則

真正省時間的不是工具，是讓 AI 第一次就給對調性，不用來回改三輪。開新對話時貼這段：

```
我在維護「大道至簡 daoissimple.com」的網站文案。改稿請遵守:

語氣
- 繁體中文,用字克制。不用驚嘆號堆疊,不用「超值」「限時」「錯過可惜」
- 說具體的事:地點、節氣、人的手做了什麼。不要說抽象的好
- 產地故事優先於功效宣稱。不要寫療效(天麻相關尤其注意,有法規風險)

品牌禁區(這些是刻意的,不要「順手優化」掉)
- 不要加 banner 輪播、彈窗、閃爍特價
- 留白很多是對的,不要為了多塞東西壓縮
- 雲南(茶褐)與台灣(苔綠)是對稱並列的雙翼,
  不要讓一邊變成主、一邊變成附屬
- 慢,是這個品牌的主張

文章分類只有四種:生活提案／產地故事／選物筆記／二地對話

改完只給我改後的文字,不要解釋,我要直接貼回 WordPress。
```

這些規矩取自 `docs/DAOISSIMPLE_SITE.md` 的〈設計取捨筆記〉。**那份筆記改了，這段也要跟著改。**

## 還沒解決的事：備份

**這跟 AI 無關，但它還在，而且比自動化重要。**

現況是「沒有 staging」+「備份不確定」，而這個站一年要發約 72 篇文章。

- **免費解**：UpdraftPlus，資料庫每日、檔案每週，遠端存到 Google Drive。
  設定完**一定要去 Google Drive 用眼睛確認檔案真的在**——網站上顯示「成功」
  只代表打包完成，傳輸那段仍可能失敗
- **付費解**：Jetpack 的 VaultPress Backup，即時備份、一鍵還原

**不要因為想接 AI 才去買 Jetpack。** 要買就因為它是備份。

## 什麼時候該重新評估

出現下列任一狀況，這份結論就該重算：

1. **發文量翻倍**（每月 12 篇以上），或改成大量短文
2. **出現不需要配圖的內容型態**——照片是這次的關鍵論證，這個前提一變，結論就變
3. **要做批次改動**——例如全站文案改版、統一調整 SEO 標題描述。
   那是一次性的大量重複工作，自動化在那種場合才真正划算
4. **官方方案變成免費或內建**——目前 Jetpack MCP 需付費方案

重算時要問的還是同一個問題：**扣掉你本來就要在後台做的事，實際還省下多少？**
